# PWA 部署與 iPhone 驗收清單

這份清單用於「好好記帳」網頁版正式發布前，以及每次更新後的驗收。

## 部署前

- [ ] 使用固定網址與 HTTPS，避免日後更換網域造成瀏覽器資料無法沿用。
- [ ] 若部署在子目錄，確認 `web/index.html` 的 `<base href>` 與實際路徑一致。
- [ ] `manifest.json`、`pwa_service_worker.js`、`sqlite3.wasm` 與 `drift_worker.dart.js` 都能直接取得，且不會被登入頁或重新導向攔截。
- [ ] 伺服器對 `sqlite3.wasm` 回傳 `application/wasm`。
- [ ] Service Worker 位於 App 網址範圍內，並以 HTTPS 提供。
- [ ] 保留上一個可用版本，以便新版本有問題時快速回復。
- [ ] 發布前執行：`flutter analyze --no-pub`、`flutter test --no-pub`、`flutter build web --release --no-pub`。

## 桌面瀏覽器驗收

- [ ] 首次連線能進入首頁，新增、修改、刪除交易後重新整理仍保留資料。
- [ ] 月曆、分析、訂閱、類別與設定頁都能正常開啟。
- [ ] 建立 JSON 備份並下載；使用同一份檔案還原後，交易、類別與訂閱數量正確。
- [ ] App 至少完整連線開啟一次後，中斷網路並重新整理，仍能離線啟動。
- [ ] 重新連線後再次開啟，能取得新版本；若畫面仍舊，完全關閉分頁後再開啟。

## iPhone Safari／主畫面 App 驗收

建議先用測試資料完成整套流程，再開始記錄真實帳目。

- [ ] 使用 Safari 開啟正式 HTTPS 網址，確認載入與導覽正常。
- [ ] 點選「分享」→「加入主畫面」，從主畫面圖示啟動 App。
- [ ] 確認以獨立視窗開啟，圖示、名稱、狀態列與直向版面正常。
- [ ] 在主畫面 App 新增一筆測試交易，完全關閉後重開，資料仍存在。
- [ ] 開啟飛航模式，從主畫面重新啟動，確認離線可用；測完後恢復網路。
- [ ] 測試 JSON 備份下載、清除資料與備份還原。
- [ ] 測試 320～430 px 寬度、橫向、放大文字，以及鍵盤開啟時表單可捲動。

## iPhone 資料注意事項

- Safari 分頁與「加入主畫面」後的 Web App 可能使用不同的本機儲存空間，不能假設兩邊的帳目會自動共用。
- 建議先加入主畫面，再固定從主畫面 App 記帳。
- 如果已在 Safari 建立資料，先建立 JSON 備份，再到主畫面 App 還原。
- 清除 Safari 網站資料、移除主畫面 App、改網址或改網域前，務必先建立備份。
- 目前是單機本機資料庫，沒有伺服器同步；遺失裝置或清除網站資料時，只能靠備份還原。

## 每次版本更新

- [ ] 更新前建立 JSON 備份。
- [ ] 在線上開啟一次，確認首頁顯示新版本功能。
- [ ] 新增一筆資料後重開 App，確認舊資料與新資料都存在。
- [ ] 再做一次離線啟動測試。
- [ ] 若資料結構有變更，特別測試舊版資料庫升級與舊備份還原。
